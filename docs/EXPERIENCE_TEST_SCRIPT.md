# 第一轮体验测试脚本（MVP · Async World）

> Sprint 4 Step 6  
> 核心假设 **H1**：玩家愿意继续  
> 环境：本地 `npm run dev`，浏览器 localStorage  
> 预计：25–40 分钟

---

## 开始前

1. `git pull && npm install && npm run dev`
2. 打开应用，清档（可重复测）：

```js
localStorage.removeItem('frontend-quest:save');
location.reload();
```

3. 准备一张纸或笔记，按场景打分（1–5）并记一句原话。

| 分数 | 含义 |
|---|---|
| 1 | 想关页面 |
| 3 | 能完成，但没有想再来一次 |
| 5 | 想继续下一题 / 明天还会打开 |

---

## 场景 A — 新玩家冷启动（约 8 分钟）

**操作**

1. 看首屏「三步开始」是否一眼能懂。
2. 点「开始定级」做完 3 题（可故意错 1 题）。
3. 看定级结果文案（是否强调「不是考试、不发 XP」）。
4. 点「按推荐开始」进入一题。

**观察**

- [ ] 是否知道下一步点哪里
- [ ] 定级是否像考试（负面）
- [ ] 是否自然进入第一道正式挑战

**记录**

| 项 | 分/笔记 |
|---|---|
| 首屏清晰度 |  |
| 定级体验 |  |
| 进入主流程顺畅度 |  |

---

## 场景 B — 失败与重试（约 6 分钟）

**操作**

1. 在一道题上故意选错并提交。
2. 读失败文案，点「再试一次」。
3. 点「需要提示」，再答对。

**观察**

- [ ] 失败是否让人羞愧 / 想弃
- [ ] 「再试一次」是否是主按钮
- [ ] 提示是否有用、不剧透过度

**记录**

| 项 | 分/笔记 |
|---|---|
| 失败文案（教练感） |  |
| 重试意愿 |  |
| 提示价值 |  |

---

## 场景 C — 连续通关与进度感（约 10 分钟）

**操作**

1. 连续通关至少 2～3 道（可用「下一题」）。
2. 每次回大厅看：等级条、任务完成度、能力掌握、任务列表状态色。
3. 看锁定任务是否显示「需先完成：…」。

**观察**

- [ ] XP / 完成度是否让人有「在变强」感
- [ ] 「下一题」是否好找
- [ ] 锁定原因是否清楚

**记录**

| 项 | 分/笔记 |
|---|---|
| 进度可视化 |  |
| 连续挑战流畅度 |  |
| 解锁理解 |  |

---

## 场景 D — 回归与复习（约 5 分钟）

**操作**

1. 在控制台模拟离开 ≥12 小时：

```js
const s = JSON.parse(localStorage.getItem('frontend-quest:save'));
s.adaptive.lastActiveAt = '2026-08-20T00:00:00.000Z';
// 可选：把某知识点 nextDueAt 设为过去以触发复习
// Object.values(s.adaptive.review || {}).forEach(r => { r.nextDueAt = '2026-08-21T00:00:00.000Z'; });
localStorage.setItem('frontend-quest:save', JSON.stringify(s));
location.reload();
```

2. 看大厅横幅（欢迎回来 / 复习）。
3. 点横幅 CTA 进入一题。

**观察**

- [ ] 是否有「被惩罚」感
- [ ] 文案是否鼓励回来继续

**记录**

| 项 | 分/笔记 |
|---|---|
| 回归文案 |  |
| 复习引导 |  |
