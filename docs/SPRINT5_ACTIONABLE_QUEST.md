# Sprint 5 — Actionable Quest Slice

> Status: Design  
> Concept focus: **Learning Adventure**（来自体验反馈 + GPT 方向，收敛为可交付切片）  
> Goal: 验证「行动 → 可见结果」是否比「点选项」更让人愿意继续（H1）  
> AI: 不接入  
> 完整 IDE / 任意代码执行: 不做

---

## 1. 为什么现在做这个

体验测试结论：当前仍是答题器。

```text
看题 → 点选项 → 对/错 → 下一题
```

用户要的是：

```text
发现问题 → 行动 → 系统发生变化 → 再尝试 → 解决问题 → 感到变强
```

Sprint 5 **不是**加题、不是再打磨文案，而是一次**交互品类实验**。

---

## 2. 概念主轴：Learning Adventure（重点采纳）

| 旧概念 | 新概念（本 Sprint 要验证的） |
|---|---|
| Quest = 一道题 | Quest = **一个需要解决的问题/情境** |
| 主操作 = 选择题 | 主操作 = **行动（改/排/选关键点）+ Run** |
| 反馈 = 正确/错误 + XP | 反馈 = **系统状态变了** + 能力说明 |
| 首页 = 题库列表 | 入口 = **事件/现场**（轻量） |
| 学习顺序 = 先考知识 | 顺序 = **先体验现象，再追问为什么** |

一句话：

> 用户不是来「答对」，而是来「把现场修好」。

知识（Knowledge）、判题、Evidence、Mastery **不推翻**，挂在行动结果之后：

```text
Adventure 场景
  → Action（受控）
  → Consequence（可见状态）
  → Evaluation（确定性）
  → Evidence / XP / Review（复用现有）
```

---

## 3. Sprint 唯一目标

**只验证一件事：**

> 行动式单关是否比传统选择题关更让人想点「下一关」。

成功：你（或内测者）明确更想继续 Adventure 关。  
失败：仍觉得点点点 / 无聊 → 换情境或操作类型，不盲目加内容量。

---

## 4. P0 范围（Vertical Slice × 1）

### 4.1 做

1. **一条 Adventure 样板关**（建议：Promise 链 / 支付成功但订单未更新）
2. **受控实验室**：有限可操作点 + Run + 确定性结果（非真沙箱）
3. **可见后果**：状态面板（支付 / 订单 / 库存等）随 Run 变化
4. **Hub 入口轻改**：主 CTA 进入「现场/当前事件」；全量题单不再作为首页主角
5. 成功页：解决了什么 + 对应能力点（可映射现有 knowledge / mastery 文案）

### 4.2 不做

- 完整 IDE、任意代码执行、网络判题
- Detective / Repair / Experiment / Boss 全玩法矩阵（概念保留，本 Sprint 只落地 **Repair 一种**）
- 重地图引擎、音效体系、账号、AI
- 重写全部旧选择题（可降级为练习场或暂藏）
- 大重构 Domain 或改坏现有 Evaluation 合约（可新增 Adventure 判定，并行存在）

## 5. 样板关：Production Incident（草案）

### 5.1 叙事（Adventure 包装）

```text
🚨 现场：结账服务异常

现象：用户已支付成功，但订单状态未更新，库存未扣减。
你的任务：找出异步流程问题并修好，再运行验证。
```

### 5.2 页面状态机

```text
intro（事件说明）
  → lab（看代码 + 状态面板 + 操作）
  → running（Run 中，可极短）
  → failed（状态仍异常 + 提示 + 再改）
  → success（状态恢复 + 掌握点 + 下一关/回 Hub）
```

### 5.3 可见状态面板（Consequence）

| 字段 | 失败示例 | 成功示例 |
|---|---|---|
| 支付 | ✅ 成功 | ✅ 成功 |
| 订单 | ❌ 未更新 | ✅ 已创建 |
| 库存 | ❌ 未扣减 | ✅ 已扣减 |

用户必须感到：**不是选项对了，是面板变了。**

### 5.4 受控操作（第一版尽量简单）

任选一种主交互（实现时定一种即可）：

| 方案 | 操作 | 说明 |
|---|---|---|
| A 排序 | 调整 `then` 链步骤顺序 | 易做、好懂 |
| B 填空 | 在 1～2 个 TODO 处选择正确调用 | 接近改码感 |
| C 选错点 | 先点选「哪一步断了」再修复 | 略多一步，偏侦探 |

**推荐 P0：A 或 B**，保证 Run → 面板变化闭环最短。

### 5.5 判定

- 纯函数 / 表驱动：操作快照 → `passed` + 各字段状态 + feedback
- 不执行用户任意字符串代码
- 可记录为一次 Quest 完成，写入 progress / evidence（字段映射在实现时定）

## 6. Hub：从题库到「今日现场」

| 现在 | Sprint 5 |
|---|---|
| 题目列表为主 | **事件卡片 / 当前关**为主 |
| 一次看清所有题 | 未解锁可迷雾或折叠 |
| 下一题 = 下一道选择题 | 下一题 = 下一现场或旧练习（若保留） |

最低改动可接受形态：

```text
[进入现场] 主按钮
当前事件标题 + 一句话
进度：节点 1 / N（简单即可）
「练习场」折叠旧选择题（可选）
```

---

## 7. 与 Sprint 1–4 的关系

| 已有能力 | Adventure 中的用途 |
|---|---|
| KnowledgeNode | 成功后挂「你刚稳固的点」 |
| Evaluation 思路 | 扩展为「操作快照判定」 |
| XP / Progress | 解决问题后发放，文案偏「修好了」 |
| Mastery / Evidence | 一次成功 = 证据，不砍模型 |
| Review / Calibration | 本 Sprint 不深化，保持兼容 |

---

## 8. 验收标准

### 功能

- [ ] 可从 Hub 进入样板 Adventure 关
- [ ] 可操作 → Run → 看到状态面板变化
- [ ] 失败可改再 Run；成功有掌握点与去向
- [ ] 全量题单不再占据首页视觉主角
- [ ] 旧存档不崩溃；测试与 build 通过

### 体验（你主观，硬指标）

- [ ] 比连做 3 道旧选择题 **更想继续**
- [ ] 能说出「我修的是什么问题」，而不只是「我选对了」
- [ ] 不觉得在做试卷
